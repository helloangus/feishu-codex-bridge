# 设计决策

## 本地 app-server，而非自行调用 API

桥接调用已登录的 `codex app-server`，复用本机 Codex CLI 的登录态、thread、审批协议、图片输入和生成图片目录；飞书只作为远程交互界面。代价是 bridge 与 CLI 版本存在兼容边界，升级后要验证会话、审批、停止、图片和卡片按钮。

## 单 stdout reader

响应和通知混在 app-server stdout。若多个调用方分别读取，`/models` 的响应可能被正在等 `turn/start` 的 worker 读走。当前 reader 按响应 ID 分发到等待队列、按通知分发到事件线程，消除竞争。

## 单 worker

`turn_text`、`last_turn_status`、`current_chat`、进度卡和审批项目目前是全局状态。单 worker 让它们一对一；代价是普通任务串行。纯卡片命令仍能即时处理，运行中切换会话/压缩会被拒绝。

## 持久化会话、模型与消息 ID

会话与模型以 `open_id + ROOT` 为键，允许一个用户在多个项目使用同一机器人。最近 1,000 个 message ID 持久化以避免重投导致重复命令或副作用任务。该机制有意偏向“至多一次处理”：记录 ID 后崩溃可能漏掉消息，但重复运行修改文件的任务风险更高，用户可以重发。

## 卡片和文本命令共存

卡片提升移动端体验，文本命令用于参数化操作、旧卡失效和无点击环境。所有回调被规范化为 `Bridge.command()`，避免两套逻辑漂移。带长说明的条目用垂直满宽按钮，短控制项用两列。

## 审批必须包含摘要

盲目“允许”不安全。审批卡优先展示操作类型、原因、命令、目录、文件路径、改动类型和截断 diff。摘要不是独立审计，用户仍需审查命令、网络访问和目录授权。

## 交付物为何用文件快照

任务前后扫描工作目录可避免依赖模型准确列出文件名，且支持非 Git 目录。工程文本通过内容比较展示本轮差异，不发送整个源码文件；已知成果格式才自动上传。缓存、依赖和编译产物在扫描阶段排除，避免 `.pyc` 被比较或交付。文本读取和文件数量有上限；无法比较时明确提示，不回退上传源码。成果文件仍按时间戳/大小识别变化，每轮附件合计最多 10 个、默认单文件 20 MiB。

## 可接受失败模式

| 情形 | 行为 |
| --- | --- |
| 卡片发送失败 | 记录错误类型后回退普通文本。 |
| app-server 退出 | 当前任务失败；尝试重启；下一条任务恢复保存会话。 |
| bridge 异常退出 | 监督器退避重启。 |
| 审批超时 | 自动拒绝。 |
| 旧停止按钮 | `task_id` 不匹配，拒绝操作。 |
| 同一消息重投 | 忽略。 |

不应随意改变：不记录敏感内容；不允许多线程读取 stdout；不通过增加 worker 获取并发；不把收件目录当交付物；不移除审批/停止的归属校验。
