# Rust 最小运行版

当前开发工作区已将飞书长连接接入 Rust 原生实现，业务、Codex 适配与 REST 也由 Rust 执行；代理、TLS、心跳和重连已通过离线专项验证，尚未部署或完成真实飞书验收，见 PLAN.md。它支持授权文本任务、串行排队、会话连续，以及 `/help`、`/cd`、`/status`、`/stop`、`/compact`、`/new`、`/resume`、`/archive`、`/archived`、`/unarchive`、`/models`、`/model`、`/plan`。服务启停、两层监督与健康恢复已实现；首次部署入口见 [Rust 部署指南](rust-deployment.md)，本批待统一验证。

## 准备

配对与恢复增强已通过离线验证：restricted 模式可仅配置 `access.pairing_code_env`，对应环境变量必须是 16–256 字节且无空白的配对码。用户发送 `/pair <配对码>`，授权写盘成功后即可使用机器人，重启保留；配对码本身不保存、不进入 Codex 提示。建议私聊配对，飞书聊天仍会保留用户输入。每分钟全局最多处理 10 次配对尝试，超过限额等待下一分钟；错误尝试不落盘，限速计数重启清零。

后台启动现在使用 `guard → supervise → run` 两层 Rust 监督，不依赖 systemd。外层接管内层异常退出后的后代，清理成功才有界重启；外层每次启动最多重试 10 次。`service stop` 优先停止外层，等待整条进程链停止（最多 60 秒），正常退出不触发重启。外层状态和日志位于 `<state>/guard/runtime/supervisor`，status 增加 `guard_running` 和 `guard_snapshot`，`supervisor_running` 现在表示任一监督层持锁。该流程已通过离线验证；外层自身被强杀仍无自动接管保证。

监督器每 5 秒检测所属桥接进程的心跳进展，启动宽限 120 秒；已有心跳连续 45 秒无更新时停止桥接并清理后代，成功后等待 30 秒再启动，失败或预算耗尽则停止。健康文件读取超时也进入清理流程，不重放未完成任务。该心跳只表示进程健康线程仍能更新，不检测所有业务逻辑停滞。上述恢复流程已通过离线测试，真实平台长时间运行仍待验收。

开发版归档恢复已通过离线验证：每次启动在连接飞书前核对本地绑定与 Codex 归档列表，完整分页成功后才一次性清除已确认归档会话的所有本地引用。空绑定不查询；其他绑定、模型/Plan 设置保留，不恢复或重放任务。核对最多 100 页、每页 100 项，总限时 60 秒；分页异常、超限或保存失败拒绝业务启动并关闭本次 Codex 子进程。远端归档成功但本地清理失败时，排除存储故障后重启可再次核对修复，不必重发归档。分页不是跨客户端原子快照，其他客户端同时修改时以本次观察结果为准；未出现在归档列表中不代表会话一定可恢复。真实外部客户端广播和飞书联调仍待验收。

开发版新增监督状态持久化：`runtime/supervisor/snapshot.json` 保存最后阶段、PID、更新时间与退避时长，`bridge status` / `service status` 通过 `supervisor_snapshot` 展示。快照保留到退出后，须结合监督锁状态判断是否存活。`runtime/supervisor/events.jsonl` 独立记录阶段变化，单文件 2 MiB、保留 3 份，文件权限 0600；后台普通 stderr 仍不保存。记录只含结构化元数据，无原始错误正文。正常停止记录 stopped，提前错误尽力记录 failed；发布失败停止本次监督，不重放业务。stop 等待锁释放后若快照不是 stopped，会返回错误并阻止该次 restart。强杀或断电可能保留旧快照，日志与快照不保证同时落盘。该批离线测试、构建、Clippy、fmt、依赖边界和空白检查已通过。

PRoot 兼容修正已通过离线验证：当前 Termux/proot Ubuntu 可读取进程 status 的 PPid，但线程 children 文件缺失。旧版清理逻辑可能错误报告后代为空；新版在该文件缺失时使用 status/PPid 枚举，读取权限错误会报错，避免不完整扫描被当作清理完成。实际 `sleep` 子进程的 pidfd 清理回归已通过。孤儿接管、目标环境权限和异常退出后的长时间运行仍需验证，在此之前不宣称后代生命周期验收完成。

新增后台控制：`bridge service --config bridge.toml start`、`stop`、`restart`、`status`。控制命令通过私有本地 socket 操作监督器；停止等待监督锁释放，重启先完成停止。启动成功只确认监督器控制通道已就绪；用 status 核对桥接心跳和连接。阶段显示 starting/running/backoff/stopping，backoff 后数字为该次等待总秒数，并非倒计时。直接 `bridge run` 不受这些后台停止命令控制。离线测试、构建和静态检查已通过。

监督模式现在要求 Linux pidfd、subreaper 和可读取的进程信息，启动前探测，缺失则拒绝启动；缺少 task/children 时回退扫描 /proc 的 PPid。桥接退出后先清理被监督器接管的遗留后代，清理失败不再重启。监督器自身强杀后的清理仍无保证，Termux 尚待实机验证；Cargo 测试环境未能稳定制造可观测的孤儿后代，因此目标平台集成测试仍是必需项。后台模式丢弃普通 stdout/stderr，业务诊断沿用 events.jsonl；监督阶段已写入独立快照与轮转日志，退出后可查询最后状态。启动确认超时且无法联系本次实例时不会强杀监督器，需先查询状态再处理。

开发版状态查询新增 `supervisor_running`，表示监督锁是否被占用；原 `running` 表示桥接运行锁。退避期间可能出现 `supervisor_running: true`、`running: false`；直接 `run` 时则可能相反。查询不创建状态目录或文件，残留的未占用锁文件不代表运行；锁占用不证明进程健康，两项也是分开观测，不能视为原子快照。本字段及锁文件校验的离线回归、构建和静态检查已通过；已提供监督阶段快照，退避秒数表示本次等待总量，并非实时倒计时。

前台监督入口为 `bridge supervise --config bridge.toml`。每次执行独立 `bridge run` 子进程；异常退出有界退避重启，正常退出停止监督。连续短时失败最多重试 10 次，运行满 60 秒重置预算。Ctrl-C/TERM 中断退避或请求子进程正常关闭，20 秒未退出则强制结束直属子进程并报错。独立监督锁避免同状态目录重复监督；`status` 同时报告桥接和监督锁及最后阶段。离线回归、构建和静态检查已通过。后台启停和后代清理已实现，正常运行建议使用外层 `bridge guard`；目标平台真实接管仍待验收。子进程日志沿用已有轮转日志，监督阶段另有独立的持久化快照与日志。

开发版新增诊断日志落盘：新版 `bridge run` 取得运行锁后，将结构化诊断写入 `<state_dir>/runtime/events.jsonl`，同时保留 stderr 输出。单文件上限约 2 MiB，轮转保留 `.1`、`.2`、`.3` 三份旧文件，日志文件权限为 0600。只保存诊断模块生成的元数据，不转存任意 stderr、Codex 输出、问题正文、答案或凭据；旧的独立 stderr 提示并非全部落盘。初始化失败拒绝启动；运行中写入失败在 stderr 报告 `log_write_failed`，不自动重试业务任务。记录逐条写入，轮转前同步，强杀或断电可能丢失末尾记录。

日志模块的离线轮转、安全文件处理和 panic 锁竞争回归已通过；真实飞书与目标平台生命周期验收仍待完成。

Rust 运行状态可通过 `target/debug/bridge status --config bridge.toml` 查询。该命令不加载凭据、不连接飞书、不创建状态目录，返回运行锁是否被占用（`running`）及最后记录的 `snapshot`。状态文件在配置状态目录的 `runtime/health.json`，包含启动/更新时间、PID 和 `starting`、`connected`、`reconnecting`、`stopped` 或 `failed`。连接状态表示最后一次观测，不是实时网络探测；`running: false` 时即使快照仍写着 connected，也不能视为在线。旧版本运行实例未持有此新增锁，须升级重启后才能使用该状态入口。

健康状态更新先写临时文件、同步后原子替换；发布失败会停止本次运行。异常返回会尽力记录 failed；强杀、断电或 abort 可能保留旧快照，由运行锁区分已退出实例。开发版主循环每 10 秒更新 `heartbeat_unix_ms`；`status` 的 `heartbeat_fresh` 在心跳距查询不超过 30 秒时为 true，过期或退出为 false，旧快照缺字段或系统时间倒退为 null。连接状态独立保留；心跳新鲜不证明网络和每个业务任务正常。监督模式会检测心跳停滞并执行有界恢复；直接 run 无自动重启。离线心跳回归、构建和静态检查已通过，真实服务验收仍待进行。

使用独立测试飞书自建应用，按 README 配置消息权限、长连接和消息事件订阅。已有生产机器人继续使用 start.sh。最小版复用 Python service.py 的 App ID 全局锁，同一用户、同一全局状态目录下，不允许两者连接同一 App ID。

```sh
cargo build --locked -p bridge-cli
cp bridge.example.toml bridge.toml
```

修改 bridge.toml 中的绝对工作区、初始目录、私有状态目录和允许的 open_id。Rust 入口不再需要 Python/adapter，旧配置中的这两个字段会被忽略。`codex` 必须已登录；保持 executable 与 args 分开，桥接不执行 shell 命令字符串。配置检查不会登录或发消息。

```sh
target/debug/bridge config check --file bridge.toml
export FEISHU_APP_ID='your-test-app-id'
read -rs -p 'Feishu app secret: ' FEISHU_APP_SECRET
export FEISHU_APP_SECRET
target/debug/bridge run --config bridge.toml
```

正常启动不读取或执行旧 `.env`。不要将凭据写进 TOML、提交或日志。若配置 proxy_env，使用对应环境变量覆盖飞书 REST、地址发现和 WebSocket 代理；未指定时按 https_proxy、wss_proxy、all_proxy（及大写形式）与 no_proxy 决策。支持 HTTP/HTTPS CONNECT、SOCKS5/5h；认证、绕过规则和 HTTP/HTTPS 隧道内 TLS 已通过离线验证，代理与 Termux 实机矩阵仍待验证。

连接断开后重新获取端点并按服务端配置重试，鉴权或代理配置错误终止运行。Pong 可局部更新连接参数；缺失 Pong 会触发重连。消息与卡片在应用确认接收后返回成功 ACK，确认超时或队列已满返回失败 ACK；这表示已接收事件，不表示 Codex 任务已经执行完成。取消运行会清理待确认任务。测试使用内存连接与模拟地址发现，不连接真实飞书。

日志 `rust_runtime_started` 表示主循环启动；`feishu_connection` 的 `Connected` 表示原生 WebSocket 握手成功，`Reconnecting` 表示连接中断后重试。连接重试不重放应用任务，ACK 仍由应用接收确认决定。历史 SDK 真实验收不代表原生实现已通过验收。

新增诊断事件输出 JSON 到 stderr，包含 `unix_ms`、`pid`、内部 `task` 编号、`status` 和 `count`。`FilesPrepared` 的数量表示输入附件数；`QuestionSent` 表示飞书确认卡片发送，`AnswerReturned` 表示答案写回 Codex 成功，`AnswerDelivered` 表示最终回复发送流程成功。`ArtifactSent` 逐项报告成果上传和消息发送结果；`FilesFinished` 只表示整理流程完成，不能替代逐项上传结果，也不能证明用户已阅读。日志不记录正文、答案、凭据或文件内容。

`Reconnect` 记录传输/协议/鉴权/代理等失败类别；`HeartbeatTimeout` 表示 Pong 超时。`Panic` 只记录 panic 发生，避免泄漏载荷；它不捕获或恢复运行，也不保证进程必定退出。`RuntimeExit` 记录 CLI 正常返回或错误返回，强杀、abort 和运行时崩溃可能没有该事件。历史无时间戳日志不能用于判断本轮重连频率或证明自动重启。

## 最小验收

1. 未授权账号发送消息，不应执行或收到业务回复。
2. 授权账号发送 `/help` 获得控制面板卡片，点击状态、目录、新建等按钮执行对应命令；`/status` 仍以文字回复。卡片发送失败时回退文字命令。
3. 发送“只回复 hello，不修改文件”，收到接收/启动提示和最终文本。
4. 连续发送两个任务，验证串行；再次提问验证复用会话。
5. 任务运行时发送 `/status` 和 `/stop`；自己的运行任务被请求中断，尚未执行的请求取消。其他用户不能中断当前任务。
6. Ctrl-C 或 TERM 关闭；确认 SDK、Codex 及所属工具进程退出。重新启动不自动回放未完成任务。
7. 全局空闲时发送 `/new`，确认新会话提示；下一条消息应创建新会话，其他用户和目录的绑定保持不变。运行、排队或正在保存接收状态时发送 `/new` 应被拒绝。此命令只清除本地绑定，不删除或归档 Codex 历史会话。
8. 发送 `/resume` 获取当前目录最近会话的卡片列表，点击按钮或复制 `/resume <ID>` 恢复旧会话，再提问验证上下文。目标必须在当前目录且空闲；存在运行/排队任务时拒绝切换。当前列表最多 8 项，卡片提供恢复、归档及列表导航，分页尚未迁移。与 Python 一致，同目录会话由授权用户共享可见，不声称提供用户级历史会话隔离。
9. `/models` 显示最多 20 项，点击模型按钮或复制 `/model <ID>` 设置后用 `/model` 查询；不存在的模型应失败且不覆盖旧设置。`/model default` 恢复 Codex 默认模型。
10. `/plan on` 后查询 `/plan` 应为开启，再发送“只分析并给出计划，不修改文件”；最终回复应包含 Codex 的计划文本。`/plan off` 返回普通执行模式。设置按用户和目录持久化，重启和 `/new` 不重置模型与 Plan 设置。
11. 从 `/resume` 列表选择测试会话，发送 `/archive <ID>` 后应在 `/archived` 中出现；所有指向该会话的本地绑定清除，模型和 Plan 设置保留。复制 `/unarchive <ID>` 取消归档，再用 `/resume <ID>` 恢复。取消归档本身不切换当前会话。归档/取消归档要求全局空闲且目标属于当前目录；历史不会删除。
12. 全局空闲时发送 `/compact`，等待“上下文压缩完成”；“已请求”仅表示受理。重启后可直接压缩已绑定会话；没有绑定时应提示先提问或恢复，不能创建新会话。压缩期间 `/status` 显示压缩中，`/new` 等变更和新任务被拒绝，需完成后重新发送；所属用户可 `/stop`，其他用户不可停止。完成、失败或中断后重新查询状态应为空闲。
13. `/cd` 显示当前目录和最多 20 个子目录命令；全局空闲时 `/cd <路径>` 可切换工作区内已有目录，支持绝对路径、相对路径、`..` 和空格。切换后提问并检查模型/Plan 设置，返回原目录应恢复原会话和设置；重启应保留用户最后选择，其他用户不受影响。运行/排队期间切换应失败；文件和越界路径不应切换或创建任何目录。
14. 对不存在的目录发送 `/cd new/child`，先收到包含完整目标路径的确认提示，此时磁盘上不应创建目录。同一用户在同一聊天中发送提示里的 `/cd-confirm <编号>`，创建目录及缺失父目录并切换；确认 10 分钟有效，一次使用。错误用户/聊天、旧目录、过期或重启后的确认不得创建。忙时拒绝不消费确认，可以空闲后重试；后续新的创建提示或成功切换目录会使旧确认失效。
15. 目录创建提示提供“确认创建并切换”按钮，文字确认命令仍可用。卡片按钮只允许发起者在同一聊天、目录和原卡片上使用，10 分钟有效，每个按钮只能执行一次；重复或过期点击提示重新打开。卡片停止按钮在任务或队列变化后失效，不能停止新任务。卡片交互回归已离线通过，实际点击和手机布局验收仍待进行。

普通测试已使用内存 IPC、临时 JSON、假 app-server 与 fake Messenger 验证链路，不使用真实凭据、不调用模型。真实飞书/CLI 验收应独立记录，不能把离线通过视作手机端验证通过。

## 明确范围与限制

- 未设置时使用普通执行模式和 Codex 默认模型；已导入或保存的模型/Plan 设置会在任务准备时加载。目录选择按用户保存并在重启时读取，首次使用采用配置初始目录；会话和模型/Plan 仍按用户和目录隔离。
- `/cd <路径>` 要求全局空闲；持久化成功后才更新当前目录，不调用进程级 chdir。路径必须解析为工作区内已有目录；任务启动前、会话恢复/归档/压缩前重新校验目录快照，失效时可用工作区内绝对路径恢复选择。子目录列表最多扫描 1,000 项并展示 20 项，不提供分页。阶段性门控差异见 [ADR 0003](adr/0003-directory-mutation-gate.md)。
- restricted 模式支持白名单、导入的已配对用户及 `/pair` 入口；配对环境变量和持久化行为见上文，新增入口待统一验证。
- 目录创建确认支持卡片按钮及文本命令，最多保留 100 项待确认请求；超时发送失效提示，不自动创建。确认命令先耐久认领，执行前重新解析原始路径并核对目标，再用目录描述符逐级创建且不跟随符号链接。创建或保存失败时不切换，可能已创建的目录会保留供人工检查，不自动删除或重试；确认已失效，须重新 `/cd <路径>`。目标已被其他进程创建时也拒绝旧确认，可重新 `/cd` 切换。
- `/help` 控制面板和目录创建确认卡片已接通；会话和模型列表也已接通卡片，显示满宽操作按钮和刷新/导航入口；从列表卡片点击刷新或最近/归档导航会更新原消息；文字命令和 /help 入口仍发送新卡片。其他回复仍为文字。卡片来源由实际发送成功的 message ID 绑定，回调仅接受本地登记的操作编号，原始命令回调不能绕过校验。登记表最多 1,000 个按钮；发送失败回退为文字命令。按钮点击复用命令处理，不生成用户聊天消息；变更命令按按钮编号耐久去重。
- 按钮通过校验后即消费，即使命令因忙被拒绝，也需刷新 `/help` 或使用文字命令重试。目录的文字确认编号仍遵循上一项所述的忙时保留规则。原卡片会移除已消费或失效的按钮，全部失效时显示重新打开提示；更新按顺序发送，失败或超时记录日志、不自动重试，后端校验仍拒绝旧按钮。更新表示按钮已消费或失效，不表示业务成功，结果仍另发文字。审批使用下述独立的任务绑定规则，卡片发送失败会拒绝请求，不提供文字同意入口。
- Plan 轮次成功完成且收到完整计划条目后，成果处理结束、没有后续排队任务时发送确认卡片，提供“确认并实施”“清空上下文后实施”“继续讨论计划”。前两项关闭 Plan 模式并把完整确认计划作为新任务提示；清空上下文先移除原绑定，再由任务准备创建新会话，原会话不归档。继续讨论保持 Plan 模式，不启动任务。计划正文最多 16,000 字节，缺失、过长、截断、失败或停止均不开放实施入口。
- Plan 选择仅接受原卡片点击，绑定本人、聊天、目录和原会话；10 分钟有效，新任务或修改会话/目录/设置会撤销旧卡片。执行前需全局空闲，先耐久认领再重新校验目录、原会话和 Plan 模式，重复点击不重复执行。卡片发送失败只展示文字和重新生成提示；状态部分保存后失败会明确提示，未启动实施、不自动重试。重启后旧卡片不能实施。真实飞书验收需覆盖三种选择、重复/跨用户点击、过期和长计划显示，本批未部署。
- `/compact` 先持久化认领，再读取并加载当前绑定的空闲会话，校验 ID 和目录，不改变绑定或模型/Plan 设置。按 [Codex 0.153.4 压缩协议](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/app-server/README.md#example-trigger-thread-compaction)，请求立即返回，运行状态由 turn 通知驱动；本实现等待请求成功响应和匹配执行身份的完成通知后才释放互斥。请求结果不确定时停止本次运行，不自动重试；压缩沿用一小时执行上限。归档与压缩的真实飞书验收按用户安排延后。
- 归档响应丢失或远端成功但本地绑定清理失败时，会报告状态不确定并停止运行，下一次启动按上述流程核对修复；不自动重发任务或远端变更。开发版已接入当前连接实际收到的 `thread/archived` 通知（整批待验证）：当前任务及会话变更结束后，先清除所有匹配本地绑定再启动后续任务，撤销待实施计划；旧连接通知忽略，保存失败停止运行。待同步集合仅保存在内存中，不保证外部客户端操作会被广播；退出期间漏通知由启动核对补偿，运行期间未收到的外部操作需重启核对。
- 修改模型/Plan 设置要求全局空闲；有运行、排队、待保存任务时拒绝，避免影响已经接收的任务。与 Python 原行为的阶段性差异见 ADR 0002；查询仍可在运行时使用。
- 命令审批显示详情及同意/拒绝按钮，仅允许当前任务用户在同一聊天、目录和原卡片点击。只批准本次请求，不保存规则或批准整个会话；原始文本 `/approve`、`/deny` 不开放。10 分钟未答复、卡片发送失败、任务停止/结束时拒绝；关闭时限时尝试回传拒绝。请求早于启动响应时等待完整执行身份确认再显示卡片，最多 32 项待审批。选择后两个按钮均失效，成功回传与执行完成分别回复；回传失败或结果不确定时停止连接，不自动重试。
- 文件修改审批按连接、线程、轮次、条目 ID 关联先到达的 `item/started` 文件修改详情，显示新增/删除/修改、路径、移动目标和差异。最多缓存 32 项，每项最多 20 个文件、原始详情 16 KiB；单字段超过 4 KiB 或卡片总量超过 24 KiB 时不能同意，不以截断详情换取同意入口。详情缺失或晚于审批到达时只提供拒绝；重复快照使同条目的待审批失效。`grantRoot` 可能包含会话级目录授权，当前仅允许拒绝，不能标记为单次授权。
- 额外权限与网络审批已完成开发，完整 workspace 验证仍需补齐：additionalPermissions 完整展示网络启用状态、读取/写入路径、文件系统规则及 glob 扫描深度；networkApprovalContext 展示主机和 HTTP/HTTPS/SOCKS5 TCP/UDP 协议。路径值按字面值引用，不展开路径规则。仅主机网络请求可缺少命令/目录；其他命令仍需两者。只提交 accept/decline，服从 availableDecisions，不接受会话缓存或持久化策略修改。未知字段/枚举或畸形参数触发协议失败；unknown 特殊路径、超过展示上限或远端执行环境只提供拒绝。grantRoot 会话目录授权仍不开放。沿用原卡片身份、一次性、超时和关闭拒绝规则；真实飞书点击与手机端详情展示仍待验收。
- 问答只由当前 Plan 轮次的真实 `item/tool/requestUserInput` 请求触发，普通回复中的问题或选项文字不会创建问答卡片。支持逐题单选，以及“其他”/无选项/敏感题自行回答，不展示或接受跳过；每题均有非空回答后整组一次回传。与审批共用最多 32 项待交互限制，绑定用户、聊天、目录、原卡片和执行身份，10 分钟总时限不随换题重置。未答完就超时/停止/结束、卡片发送失败、请求重复或过量、错误模式或身份，以及超过 20 个选项/16,000 字节无法完整展示时，停止本次桥接运行并尝试中断任务。正常关闭也不回传空或部分答案。需要重新启动服务后由用户重新发起，不自动重跑。
- 点击“其他／自行回答”后，复制提示中的 `/answer <编号> <题号> <答案>`，支持最多 16 KiB 多行答案；Plan 模式不提供跳过或 `/answer-skip`。敏感题不展示预置答案，提交的答案不在确认回复或日志中回显，但飞书聊天会保留输入。答案只在本进程内存中等待汇总，不写入任务提示或去重日志；普通聊天仍是新任务。跨用户/聊天、旧题号、重复或超时答案会被拒绝，重启后旧答案命令也不会变成任务。
- 附件支持图片、文件、音视频和富文本内图片/文件；富文本选择中文、英文或首个语言版本，保留标题说明并按资源 key 去重。每条最多 10 项、单项最多 20 MiB，仅授权并认领任务后下载。文件存入当前目录 `feishu-inbox`，使用私有暂存、清理后的文件名和逐级 no-follow 打开；下载或格式检查失败不发布半成品。图片校验 PNG/JPEG/GIF/WebP 文件头后作为 `localImage` 输入，其他附件通过本地路径交给 Codex。
- 任务前后扫描排除收件目录、依赖、缓存、构建目录、环境文件及配置的状态目录。最多扫描 10,000 项/200 文件，工程文本最多读取 256 KiB，每个差异最多展示 4,000 字符；支持新增/修改/删除和换行提示，扫描不完整时不推断删除并告知遗漏。工程文本只发差异卡，已知图片/文档/音视频/压缩包才上传。
- 当前线程生成图片也参与交付：目录取 `CODEX_GENERATED_IMAGES`，否则 `$CODEX_HOME/generated_images`，否则 `$HOME/.codex/generated_images`。只扫描本线程子目录，任务启动前建立快照。工作目录成果和生成图片按 SHA-256 内容去重，过滤大小后统一最多 10 项、每项 20 MiB；上传失败和数量/大小限制列出汇总，不自动重发。附件准备总时限 120 秒，成果处理总时限 180 秒；超时可能部分交付，会提示检查工作目录。成果处理结束前不启动下一任务或变更会话/目录，普通请求可排队。重启后不重放任务或交付。

- 运行超过约 3 秒后发送进度卡，随后最多每 3 秒更新一次，显示耗时、停止状态及前 1,000 字符预览。只保留一个等待或正在发送的进度请求，繁忙时丢弃中间预览；不会为每个 token 新建消息。进度失败后本轮停止刷新，最终回复仍单独发送。进度和最终回答在同一发送队列串行处理，先尝试把进度卡标为结束，再发完整回答，旧预览不会覆盖终态。进度和结束更新各限 5 秒，最终各段卡片/文字各限 10 秒，整份回答限 180 秒。正常退出最多等待发送队列 5 秒，超时退出可能来不及刷新卡片，不自动补发。
